## What Belongs Here

Use this folder for MVP scope, domain model, build slices, user workflows, UX decisions, feature specs, onboarding, and design-system notes.

## What Does Not Belong Here

- GTM strategy, sponsor outreach, or sales process notes; use [Business](../business/index.md).
- Competitive positioning and market evidence; use [Strategy](../strategy/index.md) or [Market](../market/index.md).
- Engineering implementation details that are not product-facing; use [Engineering](../engineering/index.md).

## When To Create A New Product Doc

Create a product doc when a feature, workflow, user-facing rule, or scope decision needs durable explanation beyond a GitHub issue. Link it to [Domain Glossary](../domain-glossary.md), [Domain Model](./domain-model.md), or [Decision Log](../decision-log.md) when it uses shared terms or makes decisions.
